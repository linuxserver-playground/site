swag

5.9.0-ls9added 3 Aug 2020x86_64 · arm64

SWAG - Secure Web Application Gateway (formerly known as letsencrypt, no relation to Let's Encrypt™) sets up an Nginx webserver and reverse proxy with php support and a built-in certbot client that automates free SSL server certificate generation and renewal processes (Let's Encrypt and ZeroSSL). It also contains fail2ban for intrusion prevention.

The reverse proxy most of the fleet sits behind, with generated proxy confs for every image.

Recent changes

  • 2026-10-20[Existing users should update:](https://github.com/linuxserver/docker-swag/blob/master/README.md#updating-configs) proxy.conf, authelia-server.conf, authentik-server.conf, tinyauth-server.conf - Update Nginx configuration to replace $http_host with $host$is_request_port$request_port for better compatibility.
  • 2026-09-09Use new X-Tinyauth-Location header in Tinyauth locations and remove duplicate auth module headers.
  • 2026-07-19Rebase to Alpine 3.24 with PHP 8.5.

// How we build

One standard for every image

  • 01

    Standardised images

    Every image is built on the same curated base. With s6-overlay each one is highly extendable, and shared base layers save you bandwidth and storage.

    About s6-overlay(opens in a new tab)
  • 02

    Regular updates

    When an upstream application, a package or the base image changes, the shared workflow rebuilds automatically. Version tags tell you exactly what each build contains.

    See the fleet
  • 03

    Transparent builds

    Every release attaches its build record: layers, files, packages, init graph and test results. This site shows all of it, and the diff to the build before.

    Explore a build
  • 04

    Real support

    Whether you are new or a veteran, someone from the team or the community is around on Discord and our forum to help.

    Get support

// Built by people like you

We need people more than money.

Every image here is kept up by volunteers in their free time. Fix the image you run, make the mod you need or bring the app you want. You don't need to know how any of this works: start an AI agent in our harness and it knows the whole system, tests in your Docker and drafts the pull request for you to check.

Start contributing Get support or donate
  • Fix an image you use › My <image> container <what goes wrong>. Reproduce it, fix it and draft the PR.
  • Make the mod you need › Make a mod that installs yt-dlp into any image, and test it.
  • Bring an app you want › I'd like <app> in LinuxServer Labs. Check it meets the bar and draft the proposal.

Volunteers building and maintaining the largest collection of community Docker images. Free and open source, always, and open to anyone who wants to help: bring an agent and pull up a chair.
