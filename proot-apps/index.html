// PRoot Apps

Desktop apps, no root required

PRoot Apps installs, updates and runs complete desktop applications on almost any Linux system, even the most locked down: all it needs is bash and curl. Every app brings its whole toolchain and lives in its own folder in your home directory.

Get started#

1 · Install proot-apps

As your own user, no sudo: this puts proot-apps and the tools it bundles in ~/.local/bin. Run it again to update. amd64 and arm64 only.

install proot-apps
rm -f $HOME/.local/bin/{ncat,proot-apps,proot,jq}
mkdir -p $HOME/.local/bin
curl -L https://github.com/linuxserver-playground/proot-apps/releases/download/$(curl -sX GET "https://api.github.com/repos/linuxserver-playground/proot-apps/releases/latest" | awk '/tag_name/{print $4;exit}' FS='[""]')/proot-apps-$(uname -m).tar.gz | tar -xzf - -C $HOME/.local/bin/
export PATH="$HOME/.local/bin:$PATH"
Keep it on your PATH, with bash completion
echo 'export PATH="$HOME/.local/bin:$PATH"' >> $HOME/.bashrc
echo 'command -v proot-apps >/dev/null && source <(proot-apps completion bash)' >> $HOME/.bashrc
Uninstall proot-apps and every app
proot-apps remove all
rm -f $HOME/.local/bin/{ncat,proot-apps,proot,jq}
[ "$(readlink $HOME/.local/bin/bwrap)" == "proot" ] && rm -f $HOME/.local/bin/bwrap
rm -Rf $HOME/proot-apps/

2 · Install an app

Pick one from the catalogue below; each card has its command. The app lands in ~/proot-apps/ with desktop and menu shortcuts that do not clash with system packages.

  • Install
    $ proot-apps install firefox
  • Update
    $ proot-apps update firefox
  • Remove
    $ proot-apps remove firefox

Any app image works, not only the catalogue's short names: proot-apps install ghcr.io/linuxserver-playground/proot-apps:firefox.

Already in our desktop images

Webtop and every image built on the Selkies base ship proot-apps. Apps install into /config, so they survive image updates, and show in the session's Apps sidebar. See Installing Applications.

How it works

Apps are container images on GHCR, unpacked into your home directory and run under proot-next (opens in a new tab), which gives each one its own root filesystem without privileges, namespaces or a daemon.

What it is not

A sandbox. PRoot runs in user space and an app can leave it; it exists to make installing easy, not to isolate. Every app is a full copy of its distribution, so it trades disk space for working anywhere.

Learn more

The proot-next documentation (opens in a new tab) explains the internals, and the proot-apps repository (opens in a new tab) covers building your own apps and local catalogues.

The engine

Powered by proot-next

Every app here runs under proot-next (opens in a new tab), our reimplementation of PRoot in Rust: chroot, mount --bind and a bubblewrap front end with no privileges, for systems where user namespaces and FUSE are off the table. Instead of stopping every system call twice with ptrace, it handles path lookups through seccomp user notification, so most of an app runs at native speed. It is also what runs Steam, Proton and Wine in containers without user namespaces.
